Floor 3 alert methods — what each method detects, and how long it takes

What this page is. Four alert rules were tested on the same Floor 3 power readings (May–September 2019). Known power changes were added in memory. The original CSV was not changed. April was used only to warm up the 28-day baseline. Unchanged windows produced 0 alerts.

What an “alert” means here. A test window “alerts” if that method fired at least once after the added change. These are controlled sensitivity tests, not confirmed AC faults and not real-world accuracy.

What “delay” means. Minutes from the first minute of the added pattern to the first alert. 0 = alerted on the same minute the change started (when that minute crossed). A range like 0–3 means the delay was not the same on every detecting window.

What “no alert” means. That method never fired on that pattern. There is no delay to report.

The four methods

  • Immediate — alerts on the first minute above the threshold.
  • Continuous20 — needs 20 uninterrupted minutes above the threshold, then alerts (typical delay 19 min).
  • Continuous30 — needs 30 uninterrupted minutes above the threshold, then alerts (typical delay 29 min).
  • 20of30 — needs 20 minutes above the threshold inside some 30-minute window (gaps allowed).

Table B — Fixed size: +1, +5, or +10 kW added to the original reading

This test answers: if we add a fixed kilowatt increase to the real reading (not forced past the threshold), how often does each method alert, and how long does it take?

Each row uses the same 504 windows (252 in May–June + 252 in July–September). A minute only counts if the new reading actually crosses the threshold. Development and validation differed by at most 4 percentage points; counts below pool both periods.

Total windows in this table: 5 patterns × 3 sizes × 504 = 7,560.

How to read Table B columns

  • Pattern — shape of the added change.
  • +kW — how many kilowatts were added to the original observed power.
  • Crossed / 504 — windows where at least one injected minute went above the threshold. If a window never crosses, every method misses it.
  • Alerts / 504 (%) — windows that produced an alert for that method, out of 504. 0 / 504 (0%) — no alert means that method never fired on that row (even if some windows crossed).
  • Delay (min) — minutes from the first injected minute to the first alert. A range means delay varied across detecting windows. no delay = no alert on that row.

Table C — Does expected load change how often +kW crosses? (30 min hosts)

This table answers: on the same hosts used for the 30-minute continuous test, how often does a +1 / +5 / +10 kW increase cross the threshold when expected power is near zero versus already at least 1 kW?

One host = one window. For Immediate, alerts equal crossings on these hosts.

How to read Table C columns

  • Expected power — hour’s median expected power before the addition.
  • Hosts — number of windows in that group.
  • +1 / +5 / +10 kW crossed — count and percent of those hosts where at least one injected minute crossed the threshold after that increase.
